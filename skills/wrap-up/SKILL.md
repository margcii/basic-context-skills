# 会话收尾

一次完成已授权的整理与核验。用户只要求核对或列建议时，给出清单即可。

## 1. 按项目约定检查两条线

先读项目的 `AGENTS.md` 和它指向的目录约定、上下文文档。以本轮用户决定、实际改动和验证证据划定范围。Git 仓库先看工作区和暂存区，区分本轮和既有改动。

- **文件和代码归位。** 检查本轮代码、测试、脚本、产物与日志是否位于项目指定目录。按既定结构修正归位，跟进受影响的导入、运行入口和链接。顺手整理限于本轮工作。
- **上下文文档。** 核对用户已确认的长期约定、实际完成状态及证据。每项信息留一个权威位置，其他地方用短链接。大胆裁剪重复、过时内容和流水账，保留独有的决策理由、原始数据与唯一证据。凭据只记录获取入口。没有项目约定时，沿用现有结构。

## 2. 在本轮完成整理

直接做授权清楚、可逆的归位与裁剪，无需先交维护清单。HANDOFF 按项目约定维护，只留当前状态、下一步、完成标准、必要阻塞和证据入口。验收文档只留结论、关键反例和原始日志索引。

涉及改变范围、规格、验收标准、权威出处，或移动会影响其他工作、删除唯一证据等关键决定时，向用户一次问齐，简述选项和影响。等确认时继续独立的整理。用户决定、建议和未验证判断分别记录。

## 3. 核验并汇报

检查两条线都已处理，复核差异、路径、运行入口、文档链接及证据与状态是否一致。按实际风险运行验证。简短汇报完成项、验证结果和仍需用户决定的事项。

用户主动触发 wrap-up 时，Git 项目默认在核验后直接做本地 commit。按项目规则只暂存本轮整理涉及的变更，检查暂存差异和敏感信息。用户限定只核对或禁止提交、项目另有规定、暂存区归属不清，或待确认决定影响提交范围时，先处理限制。发现敏感信息时暂停提交。汇报实际提交状态。全程中文，凭据不出现在报告或提交中。
